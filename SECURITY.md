# Security policy (pre-application)

Do not file secrets or personally identifying evidence in public issues or pull requests. There is no public service, issued token or live smart contract to secure yet. Report prospective design weaknesses through the repository's private maintainer channel once established; roles are not yet appointed. Future releases must add a defined vulnerability-disclosure contact and documented incident ownership before exposing any customer-facing financial surface.

Never commit wallets, seed phrases, private keys, service_role keys, database credentials, customer identity scans, unredacted disputes or privileged provider logs. Do not construe this source as a safe or audited deployment.
